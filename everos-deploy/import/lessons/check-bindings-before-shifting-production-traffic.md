# 生产切流量前核对新版本的绑定

**规则：** 生产新版本先只上传、不接流量，用 API 核对它的 secret 和绑定与线上版本一致，再切流量。

Seen 1×（2026-10-13）

## 出了什么事

- 2026-10-13 11:44 SGT，公开站 `xinyue-site` 第一次上线 `d5772a7`（版本 `937cb5a7`）后缺 secret，`/api/status` 的 `studioReady` 是 false。4 分钟后回滚到 `8b25dc32`。
- 根因（Linear PER-41，11:55 SGT 的评论）：10-11 有一个没有绑定的版本 `abef2566` 被误传到生产 Worker，新版本的 secret 是从最近上传的版本继承的。
- 后果：生产后台约 4 分钟不可用。

## 修复

不是代码提交。第二次上线（版本 `f712963b`，12:44 SGT）改成：只上传版本，secret 明确从 `8b25dc32` 继承，核对绑定的名称和类型后再切到 100%，验证失败就回滚。

## Done right

- 第一次上线前记了回滚版本，4 分钟内回滚完成。
- 13:17 SGT 摇摇荡荡上线（版本 `01c763ed`）照同一做法：secret 从 `f712963b` 继承，切换前与 `f712963b`、`8b25dc32` 都核对过。
- 上线评论写明「secret 的值 API 不返回，无法直接比对」，没有把名称一致写成值一致。
