# 验收目标是真机指标时，上生产前要有真机结果

**规则：** 任务写了真机目标（例如中端手机 60fps）时，上生产前要么有真机结果，要么在 issue 里写明谁接受了没有真机结果就上。

Seen 1×（2026-10-13）

## 出了什么事

- PER-41、PER-42、PER-43 的要求是「中端机目标 60fps」。三款 3D 游戏 10-13 都上了生产（#70、#71、#67）。
- 帧率的依据是 iMac（M1 显卡）上的无头 Chrome，和没有显卡的机器上的软件绘制。验收用的是程序玩家，不是人。每条验收和上线评论都写了「没有在真实手机上试玩」。
- 验收里已经看到的问题：M1 上帧率 56–60 时，手机尺寸仍有 3 局画质被自动降到最低档，画面发糊（PER-41）；普通模式对不认路的玩家很难（PER-41）。
- 后果：真手机上的帧率和画质现在是未知的。主要使用者用手机。

## 修复

没有。画质只降不升的规则在共用的 `three-loader.mjs` 里，PER-41 的评论建议另开一条，当天没有看到新 issue。

## Done right

- 模拟尺寸和真机分开报告，「手玩」写明是程序在真实时钟下玩、不是人也不是真手机，符合 AGENTS.md「模拟尺寸与真实设备验证须分别报告」。
- #74 把 runner 上的软件绘制帧率和本机帧率分开写，没有混成一个数。
