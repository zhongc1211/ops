# 标了「待定」的问题，上线前写下谁定的

**规则：** PR 或 Linear 里标了「待定」「待 Zack 定」「还没批准」的事，合并或上线前把谁在什么时候怎么定的写进同一个 PR 或 issue。

Seen 1×（2026-10-13）

## 出了什么事

当天三处，记录里都找不到决定：

- #72（PER-28）：草稿做好后也隐藏「查看进度」，超出了 brief。PR 正文写「需要另说」，Linear 10:39 SGT 标「待定」。11:05 合并，11:06 上生产，上线评论只写「按 PR 仍隐藏」。
- PER-43：09:26 SGT 的验收评论写「是否把 `RIVAL.pace` 从 0.14 再降到约 0.1 待 Zack 定」。09:30 提交 `e13bcb3` 改成 0.1，09:36 部署 testing，12:44 随 #70 上生产。
- 摇摇荡荡：#68–#71 的正文写它「还没批准上生产」（10:17 SGT）。13:17 它上了生产（#73、#67），PR 和 Linear 里没有批准记录。

后果：事后分不清是 Zack 定的，还是执行的 agent 自己定的。这三处可能是口头或在 box 的 `status.md` 里定的，夜审读不到那个文件，所以这里只能记「没有记录」，不能记「没有批准」。

## 修复

没有。需要补记的话写进 `docs/decisions.md`。

## Done right

- PER-27：上线评论写了「Zack 批措辞定稿」，#66 正文里「措辞可以再由营销审」的问题有了交代。
- #72 的正文主动指出哪两行超出了 brief，没有把它当成 brief 的一部分。
