卡住工作检查（复核后发送）：只做下面几步，不做别的。背景：预检脚本（stuck-check.sh --scan）每 15 分钟查一遍 iMac 和 box 两套 Orca 里 in-progress 的任务工作区，发现疑似卡住的 agent 才启动你；你复核后由脚本叫醒派活的 bot。步骤：1) 运行 ~/orca/workspaces/ops/scripts/stuck-check.sh --list。它列出每条嫌疑（S1、S2…）：哪种情况（agent_gone = agent 进程不在了；agent_idle = 停在输入框等输入超过 30 分钟；agent_silent = 进程还在但 30 分钟没有新输出）、脚本的判断、复核命令。2) 逐条复核：照它给的 orca terminal read 命令读那个终端的屏幕，只读。只有屏幕清楚显示脚本判断错了才排除：agent_idle 或 agent_silent 的，隔 20 秒读两次，屏幕内容在变（有输出在走、计时在跳）就排除；agent_gone 的，屏幕上有 agent 界面正在运行就排除。agent 说自己做完了但工作区还是 in-progress 的，不排除。拿不准的不排除。3) 运行 ~/orca/workspaces/ops/scripts/stuck-check.sh --send，要排除的加 --dismiss S<编号>=<一句原因>（可以写多个 --dismiss）；--list 说没有嫌疑但有消息没发出去时也照样运行 --send。等它结束，最多等 5 分钟。脚本自己把每条发给派活的 bot，同一工作区只报一次。4) 不要自己发消息、不要自己 POST 任何 webhook、不要调用 grok-bot-cli 或 grok-bot-mcp、不要读取或打印 ~/.config/grokbot/ 下任何文件的内容（包括 stuck-webhook.env 和 webhooks/*.env）、不要在输出里回显 URL 或 KEY、不改任何文件、不提交、不关终端、不往任何终端里输入、不动任何工作区或 PR。 5) --send 退出码为 0 时，最后一步运行 ~/.orca-state/bin/orca-ok.sh stuck-check claude，然后用一两句话报告：几条嫌疑、发了几条给谁、排除了几条和原因。6) 退出码不是 0 时（3 = webhook 重试后仍失败，没发出去的脚本下次会补发），报告退出码和输出最后 20 行，不运行 orca-ok.sh，不重试，不自己修脚本。日志在 ~/.orca-state/stuck-check/stuck-check.log。
