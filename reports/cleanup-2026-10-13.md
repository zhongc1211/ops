「内存与 CPU 日常清理」原来只有自动任务里的一段提示词，没有脚本，而且规定不动任何 claude 进程。
这次新增 `scripts/mem-cpu-cleanup.sh`，claude 进程和 Chrome helper 的处理改由脚本做。上面 08:17 那一节是它的第一次 dry-run。

改动：

- 新脚本 `scripts/mem-cpu-cleanup.sh`：规则写在文件开头的注释里。
- 自动任务「内存与 CPU 日常清理」（每天 04:37）：提示词开头加了第 0 步运行脚本；报告位置从
  `~/.orca-state/mem-cpu-cleanup/reports/` 改到本目录的 `cleanup-<日期>.md`；原有的孤儿进程清理和终端 tab 清理步骤保留。
- 新自动任务「内存与 CPU 清理（负载触发）」：每小时 07 分和 37 分做前置检查，5 分钟 load 超过 2×核数
  或内存剩余低于 25%，并且距上次清理超过 3 小时，才启动 agent 运行脚本。

脚本怎么判断：

| 项 | 做法 |
|---|---|
| 找进程 | `ps` 里名字是 `claude` 的进程（不含 Claude 桌面版），`lsof` 取 cwd |
| CPU | 进程加子进程合计，间隔 3 秒采两次取较高值 |
| 闲置和最近输出 | `~/.claude/sessions/<pid>.json` 的状态变化时间，加对话记录里最后一条消息的时间。没有用终端和对话文件的修改时间，因为闲置的会话也会定期写这两处 |
| 工作区 | cwd 所在的 Orca 工作区；不在 Orca 里的用 git 顶层目录 |
| issue | Orca 关联的 Linear issue，加工作区目录名和显示名里的 PER/FDV 编号；状态是 completed 或 canceled 算已关，查不到算没关 |
| 没提交的改动 | 已跟踪文件的改动加未跟踪文件（不含被 .gitignore 忽略的），连同 `git status` 输出一起存到 `~/archive/<工作区>/<日期>/` |

我自己定的三处，请确认：

1. issue 没关的工作区里即使有重复的 claude 也不关（规则 3 优先于规则 5）。「只留最新的那个」只用在没有 issue 编号的工作区，比如 ops 主目录。
2. 「旧版本的会话」按「同一工作区里不是最新的那个 claude」处理，没有比较 claude 程序的版本号。
3. 没有 issue 编号、只有一个 claude 的工作区，判断不了任务是否结束，一律跳过。
