# 本机台账：先列失败，再实现

- 首次建账误把旧版本当新版本、一次大量叫醒：正常模式缺账拒绝；必须显式 `--init-baseline`，完整读取所有生产 Worker 后一次写「已知」，不叫醒。已有台账不允许重建。旧 box 的「已报」和 Linear 列无法恢复。
- 台账写一半中断：同目录临时文件、flush/fsync、os.replace；不追加半行。进程中断最多留下未使用的临时文件。
- 两台同时写、同机两次重叠：生产哨兵只装在 iMac；状态目录不得同步或放网络盘。台账旁固定 lock 文件覆盖抓取、比对、落盘和发送；竞争者退出。MBA 仅有自己的未推送日志，不写生产台账。手工改账也必须持同一锁。
- Cloudflare 读不到被当作没变：fetch 非零、缺 Worker、重复 Worker、空 deployment、缺版本或版本查询失败均拒绝整轮比对；保留原账并记录查询失败，连续四次失败后限频叫醒。基线失败永不叫醒。
- iMac Python 3.9 对时间字段的小数秒位数兼容不足：RFC3339 时间先按严格形状检查，再把小数秒补齐/截到微秒交给 datetime；校验和落账共用解析器。缺字段、缺时区、非法日期仍拒绝，不把解析错误当没变。台账只显示分钟，截去亚微秒不影响显示。
- 日志无限长：仅清理脚本自己的日志，保留最近 14 天；每日超过 2 MiB 轮换一份。台账保留历史不轮换；旧 mirror/pending 不自动删，安装时人工归档。
- 残留 ssh box 导致卡住或误报：两个扫描包装和生产哨兵全改成本机调用，没有 box 重试和补传。底层未推送扫描文案里的旧日志路径本轮不改（不改提醒策略）；实际输出由包装落本机。
- 叫醒返回 400、超时或发送后崩溃：变更先持久化「未报」，通知永不改「已报」。新变更立即合并提醒全部未报；无新变更时每六小时重试全部未报，不按 notify-run 退出 0 推断送达；日志只记录发送可观察结果，失败仍未报，最多延迟六小时重试。只有人工核实报告及 Linear 后才能改已报。
- 测试开关误留在正式配置：只支持显式命令行 `--no-wake`，不读禁止发送的环境变量；仅当状态目录和台账均在系统临时目录下允许。基线无条件不发送。正式 precheck 不带此参数。
- 台账或发送状态损坏：停止比对、不覆盖台账；独立 local-errors.json 连续四次后限频叫醒。磁盘不可写时只能依赖任务 stderr，无法保证本机日志或计数落盘。
- 自定义台账却漏隔离状态：要求台账父目录等于状态目录，否则在写文件前拒绝。
- 自动任务拉起模型：shell 包装不管子进程成功失败始终 exit 1；人工看 Python 返回码和日志，不能把 precheck 的 1 当作失败证据。
