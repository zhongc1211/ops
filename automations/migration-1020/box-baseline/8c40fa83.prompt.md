box 本机内存与 CPU 日常清理（只管 box 这台机器，不碰 iMac）。目标：只结束已经没有对应在做项目的遗留进程，绝不影响任何正在跑的 agent 会话和 notify-run 包着的进程。
步骤：
1) 运行 /workspace/repos/ops/scripts/box-cleanup.sh --trigger nightly，等它结束，最多 10 分钟。脚本自己只处理「孤儿（父进程 1）、运行超过 12 小时、类型是 wrangler/workerd/vitest/esbuild/vite/next 开发服务器或无头 Chrome 桥接」的进程，且跳过 cwd 附近有 agent/notify-run 的；agent 会话（claude/codex/pi 等）只报告不处理。报告追加到 ~/.orca-state/cleanup/reports/cleanup-<新加坡日期>.md。若 ~/.orca-state/cleanup/DRYRUN 存在，脚本自动只做 dry-run。你不要自己结束任何进程，不要改脚本。
2) 诊断：uptime、free -m、ps -eo pid,ppid,%cpu,rss,etime,command --sort=-%cpu | head -25 和 --sort=-rss | head -25。用 orca worktree ps、orca terminal list 核对在做的项目。把脚本没处理但占用高的进程和原因写进同一份报告，用二级标题「HH:MM 夜间定时：诊断」追加，不改脚本写的内容。
3) 终端 tab 清理（仅 box 的 Orca）：只关已退出的普通 shell 终端，以及状态为 completed 的工作区里的终端；agent 会话、前台有编辑器或在跑命令/开发服务器的、有未提交输入的、ops 项目下的、状态查不到的一律不关，拿不准不关；一次关一个，用 orca terminal close --terminal <handle>。若 DRYRUN 存在，只列出会关哪些，不关。
4) 不发消息、不建 issue、不改代码、不提交 git、不用 sudo、不用 killall。
5) 报告写完后，最后一步运行 /workspace/repos/ops/scripts/orca-ok.sh box-mem-cpu-cleanup claude。有步骤失败就写明原因，不运行。
